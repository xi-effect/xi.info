# Cursor Skills для обновления базы знаний sovlium

Пакет для корня `xi.info`. Включает 5 навыков Cursor Agent, шаблон Playwright MCP для двух независимых браузеров и карту приоритетных пользовательских путей.

## Состав

| Skill                    | Что делает                                                                 |
| ------------------------ | -------------------------------------------------------------------------- |
| `sovlium-docs-rebuild`   | Сквозной процесс: аудит → браузер → код → MDX → QA, пакетами по 3–5 статей |
| `sovlium-docs-audit`     | Реестр всех статей/URL, дубли, устаревшие материалы, пробелы               |
| `sovlium-journey-verify` | Реально выполняет шаги репетитора и ученика через Playwright               |
| `sovlium-docs-write`     | Пишет живые инструкции по подтверждённым сценариям                         |
| `sovlium-docs-qa`        | Проверяет шаги, ссылки, MDX, сборку, утечки секретов                       |

## Установка

1. Распакуйте **содержимое** архива в корень `xi.info` с объединением каталогов. Cursor найдёт `.cursor/skills/*/SKILL.md` автоматически. Проект содержит npm workspaces; конкретный пакет для `support.sovlium.ru` агент определит по файлам репозитория.
2. Убедитесь, что соседний каталог `../xi.tutor` существует и доступен Cursor на чтение. Изменять его скиллы запрещают. Если Cursor не может прочитать его из текущего workspace, добавьте папку в workspace либо разрешите доступ к ней.
3. Скопируйте `docs-agent/.env.docs.local.example` в `docs-agent/.env.docs.local`. Вставьте **локально** 4 значения тестовых аккаунтов из вашего сообщения (почта/пароль преподавателя и ученика). В архиве никаких паролей нет.
4. Добавьте в **корневой `.gitignore`**:

   ```gitignore
   docs-agent/.env.docs.local
   docs-agent/.playwright-profiles/
   docs-agent/.auth/
   docs-agent/.tmp/
   .cursor/tmp/
   ```

   Если репозиторий или IDE синхронизируют приватные конфиги, дополнительно исключите их из индекса/синхронизации. Не коммитьте авторизованные storage state и browser profiles.

5. Настройте Playwright MCP: скопируйте **блок `mcpServers`** из `.cursor/examples/mcp.playwright.json` в существующий `.cursor/mcp.json` **с объединением**, не перетирая другие MCP. Если нет `.cursor/mcp.json`, создайте его из примера. Перезапустите или обновите MCP-серверы в Cursor Settings → MCP.
6. Убедитесь, что Agent видит **два** сервера: `playwright_tutor` и `playwright_student`. Они используют разные изолированные браузерные контексты и не делят cookies.

### Как происходит вход без передачи паролей агенту

Оба MCP-сервера используют `--secrets=docs-agent/.env.docs.local`. При заполнении страницы входа Agent передаёт **только placeholders**:

| Роль      | Email placeholder           | Password placeholder           |
| --------- | --------------------------- | ------------------------------ |
| Репетитор | `SECRET_DOCS_TUTOR_EMAIL`   | `SECRET_DOCS_TUTOR_PASSWORD`   |
| Ученик    | `SECRET_DOCS_STUDENT_EMAIL` | `SECRET_DOCS_STUDENT_PASSWORD` |

Playwright MCP подменяет placeholders на значения из локального файла при `browser_type`/`browser_fill_form`. Это поддерживаемый механизм Playwright MCP, но **не граница безопасности**: держите файл вне Git и не давайте агенту читать или выводить его содержимое. Если подмена недоступна, можно войти вручную отдельно в оба браузера. В режиме `--isolated` при перезапуске сессии потребуется повторный вход.

## Первый запуск

Откройте Cursor Agent в `xi.info` и отправьте:

```text
/sovlium-docs-rebuild

Ты находишься в корне xi.info. Сначала проведи полный аудит статей,
навигации и существующих URL базы знаний support.sovlium.ru.

Затем используй два независимых Playwright MCP-браузера
(playwright_tutor и playwright_student), реально пройди главные
пути репетитора и ученика в app.sovlium.ru и сравни с текущими статьями.

Проверяй спорные условия по коду ../xi.tutor, только на чтение.
Не описывай то, что не удалось наблюдать в интерфейсе.

После аудита актуализируй первые 3–5 P0 статей, сохраняя старые URL
или проверенные редиректы. Обнови навигацию, проверь сборку/ссылки,
запиши evidence, блокеры и план следующего пакета в docs-agent/reports/.
Никаких платежей, сторонних пользователей или необратимых действий.
```

Последующие вызовы `/sovlium-docs-rebuild` продолжают следующую партию по `docs-agent/reports/status.md`. Для отдельного этапа вызовите соответствующий skill напрямую.

## Проверяемые критерии качества

- Для **каждого критического шага** статьи есть запись об **фактическом** наблюдении в Playwright (роль, дата, UI, исход, затронутый URL).
- `xi.tutor` помогает объяснить сложные ветки, но наличие кода **не считается подтверждением**, что функция доступна пользователю.
- Неудавшаяся проверка помечается `PARTIAL`, `CODE_ONLY` или `BLOCKED`; Cursor не дорисовывает интерфейс и не выдумывает шаги.
- Сохраняются маршруты/редиректы и актуальная структура навигации; проходят реальные build/lint проверки support-пакета.
- Никаких паролей, токенов, полных invite-links и персональных данных в PR, отчётах и скриншотах.
