# sovlium Docs Agent — рабочие артефакты Cursor

Эта папка **не является частью публичной базы знаний**. Она хранит карту сценариев и отчёты о проверках. Репозиторий приложения `../xi.tutor` используется **только для чтения**.

## Файлы

- `JOURNEYS.md` — стартовый список **гипотез** пользовательских путей, которые нужно проверять в приложении.
- `reports/inventory.md` — реестр всех MD/MDX страниц support, их URL, роли и статус.
- `reports/journeys.md` — фактическая карта сценариев и покрытие документами.
- `reports/evidence.md` — наблюдения из Playwright с датами и условиями.
- `reports/unverified.md` — факты, которые не удалось подтвердить, и причины.
- `reports/status.md` — прогресс и следующий пакет статей.
- `.env.docs.local` — локальные логины/пароли, **не коммитить**. Создай на основе `.env.docs.local.example`.

## Первое использование

1. Установи **два независимых** Playwright MCP сервера `playwright_tutor` и `playwright_student`. Образец `.cursor/examples/mcp.playwright.json` следует **объединить** с существующим `.cursor/mcp.json` (не затирать другие серверы). Проверить, что инструменты **обоих** серверов доступны Agent.
2. Создай `docs-agent/.env.docs.local` из примера и добавь данные двух тестовых аккаунтов **локально**. В `.gitignore` должны быть `docs-agent/.env.docs.local`, `docs-agent/.auth/`, `docs-agent/.playwright-profiles/`, `docs-agent/.tmp/` и `.cursor/tmp/`. MCP передаёт данные по `--secrets`, а агент в поля входа вводит только `SECRET_DOCS_TUTOR_EMAIL` / `SECRET_DOCS_TUTOR_PASSWORD` и `SECRET_DOCS_STUDENT_EMAIL` / `SECRET_DOCS_STUDENT_PASSWORD`; секретный файл агенту не открывать.
3. Открой Cursor в **корне `xi.info`**. Убедись, что соседний репозиторий лежит в `../xi.tutor` (если нет — агент выявит, что сверка кода недоступна).
4. В Agent вызови `/sovlium-docs-rebuild`: аудит всего содержимого → первый пакет 3–5 P0 страниц → фактическая проверка → редактирование → QA.
5. Повтори `/sovlium-docs-rebuild`, чтобы продолжить следующие пакеты из `reports/status.md`.

Для конкретной задачи также доступны `/sovlium-docs-audit`, `/sovlium-journey-verify`, `/sovlium-docs-write`, `/sovlium-docs-qa`.

## Права и безопасность

`app.sovlium.ru` может быть боевым приложением. Эксперименты — только с подготовленными тестовыми аккаунтами, без реальных платежей, посторонних пользователей и необратимых действий. В отчётах не должно быть ключей, cookies, полных ссылок-приглашений и чужих данных. Скриншоты с чувствительной информацией нельзя коммитить.

## Подсказка для первого промпта

> Используй `/sovlium-docs-rebuild`. Ты в корне `xi.info`; исходники приложения для проверки только `../xi.tutor`. Проведи полный аудит пользовательской базы знаний, затем реально пройди через Playwright P0-пути репетитора и ученика. В первом пакете обнови 3–5 важнейших статей и их навигацию при необходимости. Каждый процедурный шаг подтверждай браузером, неопределённости фиксируй, не придумывай UI. Проверь сборку support-приложения и дай отчёт по изменённым файлам, подтверждённым действиям и оставшимся блокерам. Не меняй `xi.tutor`.
